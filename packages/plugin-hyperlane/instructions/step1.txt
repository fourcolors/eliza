# Step 1: Basic Setup & Configuration
-------------------------
Purpose: Establish core plugin services and providers for Hyperlane integration

Design Decisions:
1. Service Boundaries:
   - HyperlaneService: Manages Mailbox contract interactions and message dispatch
   - StorageService: Handles persistent storage of message state
   Justification: These services require stateful connections and external system interaction

2. Functional Core:
   - All configuration generation is pure
   - All provider functions are pure
   - All data structures are immutable
   Justification: Pure functions are easier to test, maintain, and compose

3. Type Safety:
   - Readonly types for all interfaces
   - Const assertions for configurations
   - Explicit error types
   Justification: Compile-time guarantees and immutability enforcement

Actions:
1. Core Service Types (External Integration Layer)
   ```typescript
   export interface HyperlaneService {
     // Core Mailbox interactions
     readonly getMailbox: (domain: number) => Promise<IMailbox>;
     readonly dispatch: (
       params: Readonly<DispatchParams>
     ) => Promise<Readonly<DispatchResult>>;
     readonly process: (
       params: Readonly<ProcessParams>
     ) => Promise<Readonly<ProcessResult>>;
     
     // Provider management
     readonly getProvider: (domain: number) => Provider;
     readonly getDomains: () => ReadonlyArray<number>;
   }

   export interface StorageService {
     readonly saveMessage: (
       message: Readonly<HyperlaneMessage>
     ) => Promise<void>;
     readonly getMessage: (
       id: string
     ) => Promise<Readonly<HyperlaneMessage>>;
     readonly listMessages: (
       filter?: Readonly<MessageFilter>
     ) => Promise<ReadonlyArray<HyperlaneMessage>>;
   }
   ```

2. Pure Message Types
   ```typescript
   export type HyperlaneMessage = Readonly<{
     id: string;
     sender: string;
     recipient: string;
     origin: number;
     destination: number;
     body: string;
     metadata?: ReadonlyMap<string, unknown>;
   }>;

   export type MessageFilter = Readonly<{
     origin?: number;
     destination?: number;
     status?: 'pending' | 'delivered' | 'failed';
   }>;
   ```

3. Pure Configuration Functions
   ```typescript
   export const createConfig = (
     params: Readonly<ConfigParams>
   ): Readonly<PluginConfig> => ({
     domains: new Set(params.domains),
     providers: new Map(params.providers),
     defaultIsm: params.defaultIsm,
     hooks: new Map(params.hooks)
   } as const);

   export const createProviderConfig = (
     config: Readonly<PluginConfig>
   ): Readonly<ProviderConfig> => ({
     multiProvider: createMultiProvider(config),
     storage: createStorageConfig(config),
     security: createSecurityConfig(config)
   } as const);
   ```

4. Pure Provider Functions
   ```typescript
   export const createConfigProvider = (
     config: Readonly<PluginConfig>
   ) => (): Readonly<Record<string, unknown>> => ({
     domains: Array.from(config.domains),
     providers: Object.fromEntries(config.providers),
     defaultIsm: config.defaultIsm,
     hooks: Object.fromEntries(config.hooks)
   } as const);

   export const createMessageProvider = (
     storage: Readonly<StorageService>
   ) =>
     async (
       filter?: Readonly<MessageFilter>
     ): Promise<Readonly<Record<string, unknown>>> => {
       const messages = await storage.listMessages(filter);
       return {
         messages,
         count: messages.length,
         filter
       } as const;
     };
   ```

5. Implementation Structure
   ```
   src/
     services/           # Stateful external services
       HyperlaneService.ts
       StorageService.ts
     config/            # Pure configuration functions
       createConfig.ts
       createProviderConfig.ts
     providers/         # Pure provider functions
       createConfigProvider.ts
       createMessageProvider.ts
     types/            # Shared type definitions
       hyperlane.ts
       config.ts
       provider.ts
     utils/            # Pure utility functions
       config.ts
       validation.ts
   ```

6. Test Structure
   ```typescript
   // Pure function tests with vitest
   describe('createConfig', () => {
     it('creates immutable config', () => {
       const config = createConfig({
         domains: [1, 2],
         providers: [['ethereum', 'url']]
       });
       
       expect(() => {
         // @ts-expect-error - readonly violation
         config.domains.add(3)
       }).toThrow();
     });
   });

   // Integration tests
   describe('HyperlaneService', () => {
     it('dispatches messages', async () => {
       const service = createHyperlaneService();
       const result = await service.dispatch({
         destination: 1,
         recipient: '0x...',
         body: '0x...'
       });
       expect(result.id).toBeDefined();
     });
   });
   ```
