# Hyperlane Integration Coordinator
-------------------------
Purpose: Guide the implementation of Hyperlane integration with rigorous documentation and verification

## Project Goals & Guidelines
See: [Project Goals](goals.txt)

Key Objectives:
1. **Cross-Chain Communication**  
   - **Objective**: Facilitate secure, reliable message passing between distinct blockchain networks.  
   - **Key Actions**:  
     - Integrate Hyperlane message passing for cross-chain function calls.  
     - Implement robust event and message status tracking.  
     - Verify payload integrity and authenticity.  
   - **Relevant Bounty Items**: (B) Cross-Chain Information Transfer.

2. **Warp Routes & Asset Transfer**  
   - **Objective**: Provide a seamless interface for transferring assets across supported chains.  
   - **Key Actions**:  
     - Integrate Warp Route logic.  
     - Track and confirm cross-chain transfers.  
     - Provide a clean API for token transfers.  
   - **Relevant Bounty Items**: (A) Asset Transfer via Warp Routes, (C) Warp Route Deployment.

3. **New Chain Deployment**  
   - **Objective**: Expand Hyperlane integration to new chains, ensuring easy setup and consistent security.  
   - **Key Actions**:  
     - Automate scripts for validator and ISM deployment.  
     - Infrastructure checks for chain readiness.  
     - Provide a guide for ongoing maintenance.  
   - **Relevant Bounty Items**: (D) New Chain Deployment.

4. **Functional (Pure) Design**  
   - **Objective**: Maintain immutability and stateless logic wherever possible for predictability and safety.  
   - **Key Actions**:  
     - Use pure functions for validation and data transformation.  
     - Keep side-effect operations isolated.  

5. **Error Handling & Recovery**  
   - **Objective**: Provide robust, user-friendly error messages and fallback routines for failed operations.  
   - **Key Actions**:  
     - Validate inputs before cross-chain calls.  
     - Implement retry or rollback mechanisms.  
     - Log errors with structured data for debugging.  

6. **Testing & Verification**  
   - **Objective**: Achieve comprehensive coverage for both unit and E2E cross-chain scenarios.  
   - **Key Actions**:  
     - Write unit tests for core modules.  
     - Run integration tests simulating real cross-chain calls.  
     - Cover error paths (invalid keys, network timeouts).  

7. **Documentation & Configuration Guide**  
   - **Objective**: Produce clear, developer-friendly documentation for all features, especially cross-chain flows.  
   - **Key Actions**:  
     - Provide usage examples (sending tokens, deploying routes).  
     - Include a 'Getting Started' section for `.env` setup.  
     - Highlight common pitfalls (misconfigured chain IDs, missing private keys).  

8. **Performance Optimization**  
   - **Objective**: Minimize on-chain overhead while maximizing throughput for cross-chain operations.  
   - **Key Actions**:  
     - Audit gas usage for Warp Route calls.  
     - Use caching strategies where appropriate.  
     - Consolidate redundant blockchain calls.  

9. **Security Enhancements**  
   - **Objective**: Harden plugin code against exploits and ensure safe private key storage.  
   - **Key Actions**:  
     - Leverage Hyperlane's security modules.  
     - Validate inbound messages against replay attacks.  
     - Provide guidelines on private key management.  

10. **Maintainability & Future-Proofing**  
    - **Objective**: Keep a clean, modular architecture and thorough documentation so the plugin can evolve smoothly.  
    - **Key Actions**:  
      - Separate concerns (messaging, bridging, route deployment) in distinct modules.  
      - Maintain a stable API layer.  
      - Encourage community contributions via a well-structured repo.

## Project Resumption Workflow
When returning to the project:

1. Project Status Review
   ```bash
   # Update local repository
   git fetch origin
   git status
   
   # Review recent changes
   git log -n 5
   
   # Check uncommitted work
   git diff
   ```

2. Implementation Progress
   - Review implementation-checklist.md for last completed items
   - Check current branch state and any pending changes
   - Review any open pull requests or issues

3. Environment Setup
   ```bash
   # Update dependencies
   pnpm install
   
   # Rebuild project
   pnpm build
   
   # Run tests to verify state
   pnpm test
   ```

4. Context Recovery
   - Review last modified files in git history
   - Check current step file's verification checklist
   - Review any documented blockers or dependencies
   - Check coordinator.txt for last recorded state

5. Next Steps Determination
   a. If there are uncommitted changes:
      - Review the changes for completeness
      - Complete any unfinished implementations
      - Run tests and verify functionality
      - Commit if ready, following git-commit.txt guidelines
   
   b. If last step was completed:
      - Check implementation-checklist.md for next priority
      - Review dependencies and blockers
      - Begin next task according to priorities
   
   c. If last step was incomplete:
      - Review step's verification checklist
      - Complete remaining checklist items
      - Update implementation-checklist.md
      - Follow standard completion workflow

6. Task Prioritization
   Consider:
   - Security-critical features first
   - Dependencies between components
   - Test coverage requirements
   - Documentation needs

## Step Completion Workflow
1. Complete current step's implementation
2. Run all tests and verify functionality
3. Update implementation-checklist.md
4. Review code changes and determine if a git commit is needed:
   - Have new files been added?
   - Have existing files been modified?
   - Do the changes represent a complete logical unit?
   - Are the changes ready for review?
5. If commit needed:
   - Review git-commit.txt for commit message guidelines
   - Stage changes with appropriate grouping
   - Create commit with descriptive message
   - Verify commit contents
6. Review remaining checklist items
7. Select next task based on priorities and dependencies
8. Document any blockers or dependencies

Note: Do not automatically proceed to the next numbered step. Instead:
1. Check implementation-checklist.md for completion status
2. Identify any incomplete items from previous steps
3. Select the next task that has all dependencies satisfied
4. Prioritize security-critical features

## Problem Detection and Resolution Workflow
After each task and before moving to the next:

1. Code Quality Check
   ```bash
   # Run TypeScript compiler checks
   pnpm tsc --noEmit
   
   # Run linter
   pnpm lint
   
   # Run Prettier
   pnpm format
   ```

2. Test Coverage Analysis
   ```bash
   # Run tests with coverage
   pnpm test --coverage
   
   # Check for failing tests
   pnpm test
   ```

3. Security Scan
   - Run dependency vulnerability check
   ```bash
   pnpm audit
   ```
   - Check for common security issues:
     * Exposed API keys or secrets
     * Unsafe type assertions
     * Missing input validation
     * Unhandled error cases
     * Potential memory leaks

4. Performance Check
   - Review gas optimization for cross-chain operations
   - Check for unnecessary re-renders or computations
   - Verify efficient data structures usage
   - Monitor memory usage patterns
   - Check for proper async/await usage

5. Integration Verification
   - Verify Hyperlane core service integration
   - Check cross-chain message handling
   - Validate token bridge operations
   - Test interoperability with other chains
   - Verify ISM (Inter-chain Security Module) integration

6. Plugin-Specific Checks
   - Verify ElizaOS plugin interface compliance
   - Check plugin configuration handling
   - Validate event emission and handling
   - Verify proper cleanup on plugin disable
   - Check resource management

7. Documentation Review
   - Verify API documentation accuracy
   - Check for outdated examples
   - Update changelog if needed
   - Review error messages and logs
   - Update troubleshooting guides

8. Problem Resolution
   If issues are found:
   a. Security Issues:
      - Immediately address security vulnerabilities
      - Update dependencies if needed
      - Add security tests
      - Document security fixes
   
   b. Code Quality Issues:
      - Fix type errors
      - Address linter warnings
      - Format code
      - Improve error handling
   
   c. Test Issues:
      - Fix failing tests
      - Add missing test cases
      - Improve test coverage
      - Update test documentation
   
   d. Performance Issues:
      - Optimize slow operations
      - Reduce gas costs
      - Improve memory usage
      - Update performance documentation
   
   e. Integration Issues:
      - Fix cross-chain communication
      - Update chain configurations
      - Verify message passing
      - Test with multiple chains

9. Verification After Fixes
   - Run all checks again
   - Verify no new issues introduced
   - Update relevant documentation
   - Create regression tests if needed

## Core Functionality Verification
After each task and before proceeding:

1. Build Check
   ```bash
   # Build the entire project
   pnpm build
   
   # Build plugin specifically
   cd packages/plugin-hyperlane && pnpm build
   ```

2. Character Creation Verification
   ```bash
   # Start ElizaOS
   cd ../.. && pnpm start
   
   # In another terminal, test character creation:
   curl -X POST http://localhost:3000/api/characters \
     -H "Content-Type: application/json" \
     -d '{"name": "TestCharacter", "plugins": ["hyperlane"]}'
   
   # Verify character can use Hyperlane features:
   curl -X POST http://localhost:3000/api/characters/TestCharacter/actions \
     -H "Content-Type: application/json" \
     -d '{"action": "checkDomains"}'
   ```

3. Plugin Integration Check
   - Verify plugin loads without errors
   - Check plugin configuration is loaded
   - Verify plugin services start correctly
   - Test plugin event handling
   - Check plugin cleanup on character deletion

4. Core Feature Verification
   Each step must maintain these core capabilities:
   - Character creation with Hyperlane plugin
   - Basic message sending between chains
   - Token transfer capabilities
   - Chain status checking
   - Plugin configuration management

5. Error Recovery Check
   - Verify character remains functional if:
     * Network is unavailable
     * Chain is congested
     * Message delivery is delayed
     * Token bridge is paused
   - Test graceful degradation of features
   - Verify error messages are user-friendly

6. State Management
   - Verify character state persistence
   - Check plugin state management
   - Test state recovery after restart
   - Verify no state corruption during operations

7. If Issues Found:
   a. Build Issues:
      - Fix compilation errors
      - Resolve dependency conflicts
      - Update build configuration
      - Verify all modules build
   
   b. Character Creation Issues:
      - Debug plugin initialization
      - Fix configuration loading
      - Resolve service startup issues
      - Update error handling
   
   c. Integration Issues:
      - Fix plugin registration
      - Update service connections
      - Resolve event handling
      - Fix cleanup procedures

8. Verification After Fixes
   - Rebuild entire project
   - Create new test character
   - Verify all core features
   - Test error scenarios
   - Document any workarounds

## Version Control Guidelines
See: [Git Commit Instructions](git-commit.txt)

Commit Types:
- feat: New features
- fix: Bug fixes
- docs: Documentation changes
- style: Code style changes
- refactor: Code refactoring
- perf: Performance improvements
- test: Test updates
- build: Build system changes
- ci: CI configuration changes
- chore: Maintenance tasks

Example:
```
feat(messaging): implement cross-chain message verification

- Add message verification using Hyperlane ISM
- Implement signature validation
- Add rollback mechanism

Closes #123
```
